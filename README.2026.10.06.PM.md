# 対話ログアーカイブ（2026年10月6日 午後）

## 1. サイト制作の背景と要約
* **目的:** 「我」「己」「吾」が交差する中心軸（コマ軸・零点）を定め、ぶれない思考基盤を確立する。
* **核の言語化:** 対話を通じて自身の深層にある本質（Origin / Root）を引き出し、言語化・表現する。
* **ポータル運用:** 思考の記録や制作物を順次公開・集約するためのマイポータルサイトとして機能させる。

---

## 2. GitHubにおけるファイルプレビューと拡張子（MIMEタイプ）
* **拡張子による表示制御:** 
  * `.am` などの特殊・不明な拡張子はテキスト表示となる。
  * `.md` に変更することで、GitHub上のレンダラー（ビューアー）がMarkdown（`text/markdown`）と識別し、自動的に装飾プレビューを表示する。
* **ビューアー（Viewer）の概念:**
  * 拡張子を正しく設定することで、画像（`.png`）、音声（`.mp3`）、動画（`.mp4`）などの専用ビューアーが起動し、適切な形式で表示・再生される。

---

## 3. GitHub上でのファイル操作とアイコンの意味
* **画像・動画の扱い:** GitHubのWebエディタ上ではバイナリファイルを直接新規作成（テキスト打ち込み）することは不可。お手元のファイルを `Upload files` や `git push` で追加・アップロードする。
* **フォルダ型アイコンの役割:** リポジトリ内に勝手にフォルダーを作成するボタンではなく、プロジェクトやファイルを「Workspace」等の連携ツールやAI機能で開くためのショートカット操作機能。

---

## 4. WorkspaceとVS Code連携
* **Workspace（ワークスペース）の定義:** 
  * 1つのプロジェクトに関連するファイルや設定をまとめた作業領域のこと。
  * Google Workspace（オフィスツール群）とは異なる概念。
* **Web版 VS Code への高速移動（`.` ショートカット）:**
  * GitHubのページ上でキーボードの `.`（半角ドット）を押すことで、ブラウザのまま `github.dev`（vscode.dev）のVS Code環境へ一瞬で切り替え・連携が可能。
* **Gitのステータス「A」表示:**
  * 新規追加された（Added）状態を示す。空フォルダーはコミット対象外となり、中にファイルが保存・コミットされて初めてリポジトリにフォルダーが反映される。

---

## 5. VS Code上での生成AI連携とアプローチ
* **シナリオ:** GitHub Copilot Chat や AIチャット拡張機能を使い、エディタ内で直接作成・保存。
* **画像・音声・動画:** 外部AIツール（Midjourney, DALL-E, VOICEVOX, ElevenLabs, Remotion等）や拡張機能・APIを活用し、各フォルダ（`images/`, `audios/`, `videos/`）に出力・配置する。

---

## 6. 対話型プロンプト作成（ゴールシーク型）
専用GPTsを使う方法のほか、通常のChatGPTに対して以下のプロンプトを投入することで、対話を通じて高品質な指示文を深掘り作成可能。

```text
【対話型プロンプト作成指示文】
あなたはプロのプロンプトエンジニアです。
私の目的に合った最高のプロンプトを作成するために、私と対話してください。

【手順】
1. まず、私が「何を達成したいのか（目的）」を1つ質問してください。
2. 私の回答を踏まえ、プロンプトの精度を高めるために必要な「前提条件」「制約」「ターゲット」「出力形式」などを、1回につき1〜2問ずつ順番に質問してください。
3. 情報が十分揃ったら、そのままコピー＆ペーストして使える完成版プロンプトを作成してください。
